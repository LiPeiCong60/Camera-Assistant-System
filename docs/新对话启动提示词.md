# Codex 新对话启动提示词

把下面这段复制到新的 Codex 对话窗口中，用来继续本项目的多 agent 重构开发。

```text
你现在接手本仓库 Camera Assistant 项目。

请先阅读：
docs/重构开发文档-Agent执行版.md

项目重构总原则：
手机负责画面，树莓派负责转动，服务器负责智能，后台负责管理。

当前四端划分：
1. mobile_client：手机端，负责预览、拍照、录像、关键点、骨架线、人体框、模板线框、AI 推荐框。
2. device_runtime：树莓派端，负责 TTL 总线舵机云台控制、手动摇杆、自动跟随、设备状态。
3. backend + database：服务器端，负责用户、设备、媒体、模板、AI 任务、AI Provider、大模型调用。
4. admin_web + scripts：管理员端和工程脚本，负责后台管理、一键检查、工程整理。

重要架构约定：
- 设备联动时也使用主手机摄像头作为实时画面。
- 树莓派不作为主预览画面来源。
- 树莓派第一版不负责主要关键点识别。
- 所有视觉叠加都由手机端绘制。
- 所有跨端视觉坐标都使用 0 到 1 的归一化坐标。
- 所有 AI 分析统一走服务器端，手机端和树莓派端不保存 AI Key。
- 最终照片和视频由主手机拍摄、保存相册、上传服务器。

开发要求：
- 先读文档，再动代码。
- 每次只做一个小阶段。
- 不要跨目录乱改。
- 如果涉及接口字段，先更新或确认接口约定。
- 不要让手机端、树莓派端、服务器端各自维护不同的 AI 配置。
- 不要把服务器返回的像素坐标直接画到手机屏幕，必须使用归一化坐标转换。

如果我要你开启多 agent，请按以下分工：

Agent A：
负责 mobile_client 手机端视觉、相机、拍照、录像、overlay 坐标。
只能改 mobile_client。

Agent B：
负责 device_runtime 树莓派云台控制、手动控制、自动跟随。
只能改 device_runtime。

Agent C：
负责 backend 和 database，统一媒体记录、AI 任务、模板数据、AI Provider。
只能改 backend 和 database。

Agent D：
负责 admin_web、scripts、docs，后台复用精简和工程检查脚本。
只能改 admin_web、scripts、docs。

推荐第一阶段目标：
先冻结接口和数据结构，不急着大规模改 UI。

第一阶段需要确认：
1. capture_sessions.mode 枚举。
2. ai_tasks.task_type 枚举。
3. captures/media 的照片和视频字段。
4. templates.template_data 的关键点和人体框结构。
5. ai_tasks.target_box_norm 的推荐框结构。
6. device_runtime 的 track-target 请求格式。

完成任何代码改动后，按模块运行检查：

mobile_client:
flutter analyze
flutter test

backend:
python -m compileall -q backend/app backend/tests backend/main.py backend/init_db.py

device_runtime:
python -m compileall -q device_runtime

admin_web:
npm run build

请先总结你从 docs/重构开发文档-Agent执行版.md 中理解到的架构和当前应该做的第一步，不要直接大规模改代码。
```
