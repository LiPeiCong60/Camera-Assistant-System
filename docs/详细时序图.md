# 详细时序图

本文基于当前代码真实实现整理项目核心时序图，面向方案说明、技术答辩和后续文档沉淀。

注意：

- 业务后端链路与设备运行时链路是两套不同通道。
- 手机独立拍摄主要走 `backend`。
- 设备联动、自动找角度、背景锁机位、手势抓拍主要走 `device_runtime`。
- 当前默认设备视频链路是 `WebSocket NV21 上行 + JPEG preview 下行`，不是 WebRTC 主链路。
- 下列时序图优先遵循当前代码中的真实执行顺序，不把“可能存在的未来形态”混进当前实现。

## 0. 全局总时序图

这张图用于总览整个系统的关键参与者与主链路，适合作为本文件的入口图。

它不替代后续详细时序图，而是回答两个问题：

1. 这个系统里到底有哪些核心参与方。
2. 手机独立拍摄、设备联动、后端 AI、设备端 AI、本地抓拍分别发生在哪一侧。

```mermaid
sequenceDiagram
  autonumber
  actor User as 用户
  participant App as 手机 App
  participant Camera as 手机相机
  participant Backend as 业务后端
  participant DB as PostgreSQL
  participant Uploads as uploads
  participant Provider as AI Provider
  participant Runtime as 树莓派运行时
  participant Gimbal as 云台
  participant DeviceAI as 设备端 AI
  participant Captures as 本地 captures

  User->>App: 登录 / 进入首页 / 选择功能

  Note over User,Provider: 第一段：手机独立拍摄 + 后端历史 + 后端 AI
  User->>App: 进入手机拍摄页
  App->>Backend: 获取模板 / 套餐 / 历史
  Backend->>DB: 查询业务数据
  DB-->>Backend: 返回结果
  Backend-->>App: 模板 / 套餐 / 历史

  User->>App: 点击拍照
  App->>Camera: takePicture()
  Camera-->>App: 本地照片文件

  App->>Backend: 创建 session
  Backend->>DB: 写 capture_session
  DB-->>Backend: session_id
  Backend-->>App: session 信息

  App->>Backend: 上传图片文件
  Backend->>Uploads: 保存图片
  Uploads-->>Backend: file_url
  Backend-->>App: file_url

  App->>Backend: 创建 capture
  Backend->>DB: 写 capture
  DB-->>Backend: capture_id
  Backend-->>App: capture 记录

  opt 用户发起后端 AI 分析
    App->>Backend: 请求 analyze-photo / background / batch-pick
    Backend->>DB: 创建 ai_task
    Backend->>Provider: 调用 AI Provider
    Provider-->>Backend: 返回分析结果
    Backend->>DB: 更新 ai_task
    Backend-->>App: 返回 AI 结果
  end

  Note over User,Captures: 第二段：设备联动 + 本地预览 + 云台控制 + 设备端 AI
  User->>App: 进入设备联动页
  App->>Runtime: 打开设备会话
  Runtime->>Runtime: 初始化 SessionManager / Detector / Capture / Overlay
  Runtime-->>App: session_opened

  User->>App: 启动手机推流
  App->>Camera: startImageStream()
  loop 实时推流
    Camera-->>App: NV21 frame
    App->>Runtime: WS mobile-ws 推送帧
    Runtime->>Runtime: 帧循环检测 / 构图 / 跟踪 / overlay
    opt 需要控制云台
      Runtime->>Gimbal: pan / tilt 控制
      Gimbal-->>Runtime: 控制完成
    end
    Runtime-->>App: WS preview-ws 回传 JPEG 预览
  end

  opt 自动找角度
    User->>App: 启动自动找角度
    App->>Runtime: POST angle-search/start
    Runtime->>Gimbal: 扫描多个候选角度
    Runtime->>Captures: 保存候选帧
    Runtime->>DeviceAI: 分析候选角度
    DeviceAI-->>Runtime: 返回最佳角度建议
    Runtime-->>App: angle search result
  end

  opt 背景锁机位
    User->>App: 启动背景锁机位
    App->>Runtime: POST background-lock/start
    Runtime->>Gimbal: 扫描多个候选机位
    Runtime->>Captures: 保存候选帧
    Runtime->>DeviceAI: 分析人物与背景关系
    DeviceAI-->>Runtime: 返回锁定建议
    Runtime-->>App: lock result / fit_score / target_box
  end

  opt 手动抓拍或手势抓拍
    Runtime->>Captures: 保存本地抓拍
    Captures-->>Runtime: capture_path
    Runtime-->>App: 返回 latest_capture / capture_list
  end
```

### 阅读方式

这张总图建议这样理解：

1. 上半段是手机独立拍摄链路。
2. 下半段是设备联动链路。
3. `backend + DB + Uploads + Provider` 组成业务后端闭环。
4. `Runtime + Gimbal + DeviceAI + Captures` 组成设备侧现场闭环。
5. 手机 App 是唯一同时连接这两套闭环的用户入口。

## 2. 手机独立拍摄后发起后端 AI 分析

这条链路对应后端 AI 分析，包括单张分析、背景分析和历史沉淀。

```mermaid
sequenceDiagram
  autonumber
  actor User as 用户
  participant App as mobile_client
  participant Backend as backend
  participant DB as PostgreSQL
  participant Provider as AI Provider

  User->>App: 点击 AI 分析
  App->>Backend: POST /mobile/ai/analyze-photo
  Backend->>DB: 校验 capture/session
  DB-->>Backend: capture 存在

  Backend->>DB: 创建 ai_task(status=pending)
  DB-->>Backend: task_id

  Backend->>Provider: 发送图片与提示词
  Provider-->>Backend: 返回分析结果

  alt AI 调用成功
    Backend->>DB: 更新 ai_task(status=succeeded,result_score,result_summary)
    DB-->>Backend: 更新完成
    Backend-->>App: 返回 task 结果
  else AI 调用失败
    Backend->>DB: 更新 ai_task(status=failed,error_message)
    DB-->>Backend: 更新完成
    Backend-->>App: 返回失败任务信息
  end

  App->>Backend: GET /mobile/history/captures
  Backend->>DB: 读取 capture + latest_ai_task
  DB-->>Backend: 历史抓拍列表
  Backend-->>App: 返回历史列表
  App->>App: 刷新历史记录缓存
  App-->>User: 显示评分、总结、建议
```

## 3. 设备联动会话建立与实时预览闭环

这条链路对应当前默认的设备联动模式：手机向树莓派推 NV21 帧，树莓派回传 JPEG 预览。

```mermaid
sequenceDiagram
  autonumber
  actor User as 用户
  participant App as DeviceLinkPage
  participant Camera as 手机相机
  participant RuntimeApi as device_runtime API
  participant Session as SessionManager
  participant Detector as Detector/FrameProcessor
  participant Gimbal as GimbalController

  User->>App: 打开设备联动页
  App->>App: 加载后端模板、设备模板、草稿连接信息
  App->>App: 启动状态轮询

  User->>App: 点击“打开设备会话”
  App->>RuntimeApi: POST /api/device/session/open
  RuntimeApi->>Session: 创建或替换当前 session
  Session->>Session: 初始化 RuntimeState / Capture / AI / Overlay
  RuntimeApi-->>App: session_opened=true

  App->>RuntimeApi: WS /api/device/preview-ws
  RuntimeApi-->>App: 等待 preview 回传

  User->>App: 点击“启动手机推流”
  App->>Camera: startImageStream()
  Camera-->>App: 连续 NV21 帧

  App->>RuntimeApi: WS /api/device/stream/mobile-ws
  loop 每帧或节流后每帧
    Camera-->>App: CameraImage(NV21)
    App->>RuntimeApi: 推送 frame bytes + metadata
    RuntimeApi->>Session: 写入 mobile_push_frame_store
  end

  Session->>Detector: 后台帧循环读取最新帧
  Detector-->>Session: 人体/人脸/手部检测结果
  Session->>Session: 计算 tracking / compose / overlay / AI 状态
  opt 当前模式需要控制
    Session->>Gimbal: 输出 pan/tilt 控制
    Gimbal-->>Session: 控制完成
  end

  App->>RuntimeApi: WS /api/device/preview-ws
  loop 预览回传
    Session-->>RuntimeApi: 当前 preview JPEG
    RuntimeApi-->>App: JPEG preview frame
    App-->>User: 显示设备预览与 HUD 状态
  end
```

## 5. 自动找角度

这条链路对应设备端 AI 的“角度搜索”能力。它不是后端历史 AI，而是设备现场决策能力。

```mermaid
sequenceDiagram
  autonumber
  actor User as 用户
  participant App as DeviceLinkPage
  participant RuntimeApi as device_runtime API
  participant Session as SessionManager
  participant AI as AIOrchestrator
  participant Capture as CaptureTrigger
  participant Gimbal as GimbalController
  participant DeviceAI as Device-side AI Assistant

  User->>App: 点击“自动找角度”
  App->>RuntimeApi: POST /api/device/ai/angle-search/start
  RuntimeApi->>Session: 启动 angle search 任务
  Session->>AI: start_angle_search()
  RuntimeApi-->>App: angle_search_running=true

  loop 候选角度扫描
    AI->>Gimbal: 调整到候选 pan/tilt
    Gimbal-->>AI: 到位
    AI->>Capture: 保存当前帧为候选图
    Capture-->>AI: candidate_path
  end

  AI->>DeviceAI: 批量分析候选角度图片
  DeviceAI-->>AI: 返回最佳角度建议(best candidate + score + summary)

  AI->>Session: 写入 last_angle_search_result
  Session-->>RuntimeApi: ai_status 可查询

  App->>RuntimeApi: GET /api/device/ai/status
  RuntimeApi-->>App: 返回最佳角度建议
  App-->>User: 展示建议角度与说明

  opt 用户选择应用建议
    User->>App: 点击“应用角度”
    App->>RuntimeApi: POST /api/device/ai/apply-angle
    RuntimeApi->>Session: 应用 recommended_pan_delta / tilt_delta
    Session->>Gimbal: 执行最终转动
    Gimbal-->>Session: 调整完成
    RuntimeApi-->>App: 返回最新 status
  end
```

## 7. 手势抓拍与 3 秒倒计时

这条链路对应设备端实时手势识别后的自动抓拍。抓拍结果默认保存本地，不自动写后端历史。

```mermaid
sequenceDiagram
  autonumber
  participant Camera as 手机推流帧
  participant Session as SessionManager
  participant Detector as Detector/FrameProcessor
  participant Gesture as GestureCaptureState
  participant RuntimeApi as device_runtime API
  participant Disk as device_runtime/captures
  participant App as DeviceLinkPage

  loop 实时检测
    Camera-->>Session: 最新视频帧
    Session->>Detector: 手部/人体检测

    Session->>Gesture: 更新手势状态机

  end
```

## 12. 关键结论

从当前时序上看，系统可以明确分成三类能力：

1. 联网强依赖链路
   手机独立拍摄写历史、后端 AI 分析、历史同步。
2. 设备本地保底链路
   设备抓拍、手势抓拍、设备端 AI、自动找角度、背景锁机位。
3. 本地缓存回退链路
   模板列表、历史记录读取失败后的缓存展示。

因此当前项目已经具备：

- 设备侧本地抓拍保底
- 历史与模板的本地缓存降级

但尚未具备：

- 手机独立拍照的完整离线补传闭环
- 设备抓拍自动同步到后端历史
